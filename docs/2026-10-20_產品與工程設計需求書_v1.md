# AI Statistical Platform：產品與工程設計需求書

> 原始文件版本 v0.1（Initial Design），由 BOB 於 2026-10-20 提供，本檔為原文存檔。
> 實作規格以 `docs/2026-10-20_PRD_AI統計平台.md` 為準；兩者衝突時以 PRD 的「實作決策」為準。

- 目標用戶：研究生、護理研究者、醫療研究人員、統計初學者
- 產品定位：Open-source AI-native Statistical Analysis Platform
- 開發原則：Open Source First、CLI First、AI Native、Reproducible、Educational

---

## 1. 專案願景

### 1.1 核心目標

建立一套開源、可擴充、可供 AI Agent 操作的統計分析平台。使用者不需要具備完整統計學或程式設計背景，也能透過自然語言完成：

1. 資料匯入與資料品質檢查
2. 研究設計與變項辨識
3. 統計方法選擇
4. 統計分析執行
5. 結果驗證
6. 統計圖表生成
7. 學術結果解讀
8. APA 7 統計結果撰寫
9. 統計知識教學
10. 完整分析成果保存與重現

本平台不以複製 IBM SPSS 的所有功能為首要目標，而是重新設計 AI 時代的統計分析工作流程。

### 1.2 核心產品理念

**Statistical Analysis Should Be Explainable, Reproducible, and Accessible.**

統計分析不應只是產出 p value，而應讓使用者理解：為什麼選擇這種統計方法？研究設計是否符合分析條件？分析結果是否可信？結果具有什麼實際意義？如何重新執行與驗證？

### 1.3 主要使用情境

使用者：「我有一份 50 位護理學生的前後測資料，想知道 AI 教學介入後是否有改善。」

系統應完成：辨識前後測資料結構、確認是否為同一批受試者、進行資料品質檢查、提出配對樣本分析方案、說明方法選擇依據、經確認後執行統計、報告效果量與信賴區間、解釋統計結果及研究限制、產生可重現的程式碼與結果報告。

## 2. 核心技術架構（五層）

- **Layer 1 使用者互動層**：CLI、AI Coding Agent、未來 Web GUI、未來 Desktop Application。第一階段以 CLI 為主。
- **Layer 2 AI Agent Orchestration**：由單一 AI 模型負責流程協調，首批支援 Claude Code、Codex、Cursor；不要求同時執行多個大型語言模型；透過 Skills、Tools、MCP 及結構化流程完成專業分工。
- **Layer 3 Statistical Skills**：

| Skill | 職責 |
|---|---|
| Data Inspector | 資料結構與品質檢查 |
| Research Designer | 研究設計辨識 |
| Statistical Planner | 統計方法規劃 |
| Assumption Checker | 統計假設檢查 |
| Statistical Executor | 呼叫分析引擎 |
| Result Reviewer | 統計結果審查 |
| Statistical Tutor | 統計教學 |
| Report Generator | 學術報告生成 |
| Visualization | 統計視覺化 |
| Reproducibility Manager | 分析紀錄與重現 |

  每個 Skill 應具有：明確觸發條件、輸入 Schema、輸出 Schema、錯誤處理、工具使用限制、執行紀錄、測試案例。

- **Layer 4 統計執行層**：可替換的 Statistical Engine Adapter。優先整合 R、Python（SciPy、statsmodels）、PSPP；選配 IBM SPSS Statistics 與其他開源統計工具。所有分析數值必須由實際執行引擎計算，LLM 不可自行捏造統計輸出。
- **Layer 5 資料與成果管理層**：CSV / Excel / SAV 匯入、資料庫連線、資料字典、資料版本控制、分析結果保存、Audit Log、分析重現、成果匯出。

## 3. 自有 CLI 規格

暫定 CLI 名稱 `aistat`（正式名稱未決定）。

```bash
aistat init
aistat import dataset.xlsx
aistat inspect
aistat plan
aistat analyze
aistat review
aistat report
aistat export

aistat analyze --engine r|python|pspp|spss
aistat analyze --method paired-t-test|independent-t-test|chi-square|anova|linear-regression
aistat ai
```

- SPSS 功能應在安裝環境、授權及 Adapter 可用時才能啟動。
- CLI 應驗證參數、資料型態與統計方法的相容性。
- CLI 核心指令不可完全依賴 AI 才能使用；使用者應能在不連接 LLM 的情況下執行已定義的統計分析。

AI 模式互動範例：

```text
User: 幫我分析這份前後測資料。
AI:   已辨識 50 位研究參與者。研究設計：單組前後測。候選統計方法：配對樣本 t 檢定。
      需要確認：前後測是否來自相同受試者？是否存在缺失配對資料？
      完成確認後，將產生分析計畫。
```

## 4. MCP 整合設計

建立本平台自己的 MCP Server，預計提供：`list_datasets`、`inspect_dataset`、`get_data_dictionary`、`create_analysis_plan`、`validate_analysis_plan`、`execute_statistical_analysis`、`retrieve_analysis_results`、`review_statistical_results`、`generate_statistical_report`、`export_analysis_bundle`。

MCP Server 僅負責提供標準工具介面；統計邏輯與計算集中於獨立 Core Engine；CLI、MCP 與未來 GUI 共享同一個核心服務，避免不同入口使用不同統計規則。

## 5. JEV 審查機制

結構化三態審查：YES（符合要求）、NO（不符合要求）、UNCERTAIN（資訊不足或需要人工確認）。第一版設置兩道主要審查關卡。

**Gate A：分析執行前**——研究設計辨識是否正確、變項尺度是否正確、統計方法是否適合、配對結構是否明確、統計假設是否需要檢查、缺失資料策略是否合理。未通過時停止受影響分析。

**Gate B：報告輸出前**——結果是否來自實際分析引擎、統計數值是否與原始輸出一致、p value 是否正確呈現、效果量與信賴區間是否合理、是否過度推論因果關係、APA 7 描述是否對應實際結果。

每項判斷需保存：

```json
{
  "gate": "method_validation",
  "check_id": "research_design_check",
  "verdict": "UNCERTAIN",
  "evidence": [],
  "reason": "尚未確認前後測是否為相同受試者",
  "required_action": "request_user_confirmation"
}
```

JEV 屬於流程審查機制，並非統計正確性的絕對保證。

## 6. AI 統計教學系統

- **Research Mode**：快速完成可靠且可重現的統計分析；簡潔解釋、快速執行、自動生成結果、完整分析紀錄。
- **Learning Mode**：協助統計初學者建立方法學知識。每次分析需回答：(1) 目前的研究問題是什麼？(2) 為什麼選擇這項統計方法？(3) 為什麼不選其他方法？(4) 如何理解統計假設？(5) 如何解讀效果量與信賴區間？(6) 這個結果可以支持什麼結論？教學說明應使用使用者自己的研究資料與研究設計作為例子。

## 7. 第一階段 MVP

**必須完成**：CLI 安裝與初始化、Excel / CSV 匯入、資料預覽、資料品質檢查、資料字典、描述性統計、配對樣本 t 檢定、獨立樣本 t 檢定、卡方檢定、相關分析、基本線性迴歸、R 統計引擎、AI Skills 工作流程、JEV Gate A / B、分析結果匯出、APA 7 報告草稿、分析執行紀錄。

**後續版本**：PSPP Adapter、SPSS Adapter、資料庫 Connector、Web GUI、進階迴歸模型、重複量數與混合模型、存活分析、正式 Meta-analysis、多模型交叉驗證、自動化統計分析 Pipeline。

注意：資料來源整合與正式 Meta-analysis 應設計為兩個不同的功能模組。

## 9. 分析狀態機

```text
CREATED → IMPORTED → PROFILED → PLAN_DRAFTED → JEV_GATE_A → USER_APPROVAL
→ EXECUTING → EXECUTED → JEV_GATE_B → REPORT_GENERATED → EXPORTED
附加狀態：BLOCKED、FAILED、CANCELLED
```

關鍵原則：分析計畫未經核准，不得執行正式分析；執行失敗時不得產出宣稱已驗證的報告。

## 11. 安全及資料治理

去識別化、權限控制、原始資料唯讀、敏感資料不寫入一般日誌、未經授權不得傳送病人資料至外部模型、資料庫連線優先唯讀、執行工具需要命令白名單及逾時控制、可追溯所有資料修改與統計執行。AI 應提出統計建議，而不是在未經確認時自行更改研究資料或研究假設。

## 13. 非功能性需求

Reliability（相同資料、方法、設定與引擎版本產生可重現結果）、Extensibility（新增引擎不需修改 CLI 或核心流程）、Explainability（每個方法提供選擇理由與適用條件）、Auditability（可追溯任一報告數值的原始計算結果）、Interoperability（CLI、MCP、Agent、GUI 使用一致資料契約）、Privacy（預設本機處理）、Testability（核心統計功能以已知測試案例與數值容許誤差驗證）。

---

## 14. 驗收標準

1. 可以安裝並啟動 CLI。
2. 可以匯入研究資料。
3. 可以檢查資料結構與品質。
4. 可以產生統計分析計畫。
5. 可以通過 JEV Gate A 或明確說明無法通過的原因。
6. 必須經使用者確認後才能執行。
7. 可以使用實際統計引擎完成分析。
8. 可以保存分析程式碼與原始輸出。
9. 可以完成 JEV Gate B。
10. 可以產生學術結果草稿與教學說明。
11. 可以重新執行分析並核對輸出。
12. 必須正確處理資料錯誤、執行錯誤與工具不可用的情況。

## 15. 開發里程碑

- Phase 0 Technical Foundation：CLI 技術框架、核心資料模型、專案結構、授權、測試資料集。
- Phase 1 Statistical Core：R Adapter、CSV / Excel 匯入、描述性統計、基礎推論統計、結果匯出。
- Phase 2 AI Integration：AI Skills、MCP Server、自然語言分析規劃、JEV Gate A / B。
- Phase 3 Research Experience：Learning Mode、APA 7 報告、成果包、完整分析追蹤。
- Phase 4 Ecosystem：PSPP / SPSS 整合、更多統計方法、資料庫連接、Web GUI、社群擴充套件。

## 16. 待決設計事項

專案正式名稱、CLI 框架及封裝方式、核心 API 的具體 Schema、R 與 Python 的職責分工、PSPP / SPSS 相容層的實作範圍、第一版優先支援的統計方法、桌面 GUI 是否採 Web 技術、是否允許使用者自訂 Skills、本機 LLM 與雲端 LLM 的支援策略、開源授權與第三方依賴治理。

## 17. 產品設計原則

本專案不是 SPSS 的介面複製品。它應該是一套：**統計引擎開源、AI 能理解、使用者能學習、分析能驗證、成果能重現的現代化統計平台。** 第一階段優先確保統計計算正確、資料安全、使用流程簡單及成果完整。
