# PRD：aistat v0.2：無母數方法、單因子 ANOVA 與統計圖表

延續 `docs/2026-10-20_PRD_AI統計平台.md`（v0.1）。範圍與決策來自 2026-10-21 與 BOB 的兩輪 grill-me 訪談。

## 問題陳述（Problem Statement）

v0.1 的 Gate B 在統計假設不符時，會建議改用 Wilcoxon、Mann-Whitney 或 Fisher's exact test，但平台本身還不能執行這些方法，研究者只能換別的軟體。研究中很常見的三組以上比較（例如三個病房、三種衛教方式）目前也沒有方法可用。另外，報告裡完全沒有圖。需求書第 1.1 節把「統計圖表生成」列為核心目標，研究者也需要圖來檢查資料、寫進論文。

## 解決方案（Solution）

1. 新增三個無母數方法：`wilcoxon-signed-rank`、`mann-whitney-u`、`fisher-exact`。它們跟現有方法一樣經過 Gate A、研究者核准、R / Python 引擎執行、Gate B、APA 7 報告與 Learning Mode。
2. 新增 `aistat plan --alternative-of RUN`：Gate B 建議替代方法時，研究者用一個指令就能沿用同一組變項建立替代計畫。新計畫仍要通過 Gate A 並由研究者核准，原分析不受影響。
3. 新增 `one-way-anova`：主要報告 Welch ANOVA 與 Games-Howell 事後比較，同時列出傳統 F 檢定與 Tukey HSD 供對照。
4. 每個方法自動產生 1–2 張符合 APA 7 版面的圖（PNG + SVG），放在 run 資料夾並嵌入報告。

## 使用者故事（User Stories）

1. 身為研究者，當配對 t 檢定的差值不符常態時，我想執行 Wilcoxon signed-rank test，以便得到不依賴常態假設的結果。
2. 身為研究者，我想用 ordinal 尺度（例如 Likert 題項）做前後測比較，以便不必把 ordinal 硬當成 scale。
3. 身為研究者，當獨立 t 檢定的組別不符常態時，我想執行 Mann-Whitney U test，以便比較兩組的分布位置。
4. 身為研究者，當 2 × 2 交叉表的期望次數太小時，我想執行 Fisher's exact test，以便得到正確的 p 值。
5. 身為研究者，我想在 Fisher's exact test 中得到勝算比（odds ratio）與 95% CI，以便描述關聯的強度與方向。
6. 身為研究者，我希望無母數方法也報告效果量（r 與 rank-biserial r），以便符合 APA 7 要求。
7. 身為研究者，我希望報告寫出中位數與四分位距，以便讀者理解無母數結果代表的位置差異。
8. 身為研究者，我希望系統依樣本數與同分情況選擇 exact 或常態近似 p 值，並在報告中寫明用了哪一種，以便審查者能核對。
9. 身為研究者，當 Gate B 指出假設不符時，我想執行 `aistat plan --alternative-of RUN_xxx` 建立替代分析，以便不必手動重打變項。
10. 身為研究者，我希望替代計畫一樣要經過 Gate A 與我的核准，原分析保持不變，以便兩份分析都留有完整紀錄。
11. 身為研究者，我希望報告與 Gate B 訊息直接寫出可執行的替代指令，以便知道下一步要做什麼。
12. 身為研究者，我想用 `--method one-way-anova --var outcome=Y --var group=G` 比較三組以上的平均數。
13. 身為研究者，我希望 ANOVA 預設採用不假設變異數相等的 Welch ANOVA，以便在各組人數或變異不同時仍可靠。
14. 身為研究者，我想看到 Games-Howell 事後比較的每一對組別差異、CI 與校正後 p 值，以便知道是哪幾組不同。
15. 身為研究者，我也想看到傳統 F 檢定與 Tukey HSD，以便和期刊常見的寫法對照。
16. 身為研究者，我想得到 η² 與 ω² 效果量，以便描述組別差異能解釋多少變異。
17. 身為研究者，我希望 ANOVA 檢查各組常態性與變異數同質性，並在不符時建議 Kruskal-Wallis test，以便知道結果的前提是否成立。
18. 身為研究者，我希望分組變項只有兩組時 Gate A 建議改用 t 檢定，以便選擇最合適的方法。
19. 身為研究者，我希望每次分析自動產生圖：配對設計用前後測線圖，兩組或多組比較用箱形圖加資料點，相關用散布圖，迴歸用殘差圖，卡方 / Fisher 用堆疊長條圖，描述統計用直方圖或長條圖，以便檢查資料與放入論文。
20. 身為研究者，我希望圖同時有 PNG（放 Word）與 SVG（可縮放、投稿用）兩種格式。
21. 身為研究者，我希望圖的版面符合 APA 7：圖本身不放標題，報告中以「Figure 1」與斜體標題說明，以便直接用在論文。
22. 身為研究者，我希望中文欄位名稱在圖上正確顯示，以便不必改欄位名稱。
23. 身為研究者，我希望畫圖的程式碼 `figures.py` 存在 run 資料夾並可以重跑，以便圖也能重現。
24. 身為研究者，我希望圖上不出現統計引擎沒算過的數字，以便圖與報告一樣可以追溯。
25. 身為研究者，我希望沒有中文字型或畫圖失敗時，報告照樣產生並清楚說明原因，以便不會因為圖表卡住整個流程。

## 實作決策（Implementation Decisions）

### 無母數方法（PR 1）

- **Wilcoxon signed-rank**：角色 `before`、`after`（scale 或 ordinal，數值）。差值 = after − before，差值為 0 的配對依 Wilcoxon 原法排除。非零配對 n ≤ 50 且差值絕對值沒有同分時用 exact p，否則用常態近似（同分校正變異數、連續性校正）。兩引擎都以明確參數指定，結果一致（R `wilcox.test(exact=, correct=TRUE)`、SciPy `wilcoxon(method=, correction=True)`）。統計量報告 W+（正差值等級和，等於 R 的 V），由引擎自行計算，不使用 SciPy 預設的 min(W+, W−)。
- **Mann-Whitney U**：角色 `outcome`（scale 或 ordinal，數值）、`group`（恰好兩組，每組至少 2 筆）。n1 + n2 ≤ 50 且沒有同分時用 exact p，否則用常態近似加連續性校正。統計量報告第一組的 U（等於 R 的 W）。
- **效果量**：r = Z / √N，其中 Z 由引擎以同分校正、不含連續性校正的常態近似計算，N 為有效樣本數（signed-rank 為非零配對數）；另報告 rank-biserial r（signed-rank 為 (W+ − W−) / (W+ + W−)；Mann-Whitney 為 2U / (n1·n2) − 1）。兩者都以 Cohen 的 .1 / .3 / .5 標準描述大小。
- **描述統計**：signed-rank 報告前後測與差值的中位數、Q1、Q3；Mann-Whitney 報告各組中位數、Q1、Q3。
- **Fisher's exact test**：角色 `row`、`column`，兩者都必須恰好兩類（只支援 2 × 2）。p 值使用 R `fisher.test` 與 SciPy `fisher_exact` 的雙尾結果（兩者一致）。勝算比採條件最大概似估計（conditional MLE，與 R `fisher.test` 相同），CI 由非中心超幾何分布反推。兩引擎以相同演算法、同樣嚴格的求根容許誤差計算，因此兩者一致；R 與 SciPy 內建 CI 的求根精度不足（相差可達 1%）。觀察值落在支撐邊界時，對應的 CI 端點為 0 或 ∞（輸出 null，報告寫「∞」）。
- 這三個方法沒有需要另外檢定的統計假設（`assumptions_planned` 會說明不需常態假設）。

### 替代計畫（PR 1）

- `Workspace.create_alternative_plan(run_id)`、CLI `aistat plan --alternative-of RUN`、MCP `create_analysis_plan(alternative_of=...)`。
- 對應：`paired-t-test` → `wilcoxon-signed-rank`；`independent-t-test` → `mann-whitney-u`；`chi-square`（2 × 2）→ `fisher-exact`；`correlation`（pearson）→ `correlation`（`method=spearman`）；`one-way-anova` → `kruskal-wallis`（本階段尚未實作，回報明確錯誤）。沒有對應的方法回報錯誤。
- 沿用原計畫的資料集與變項角色，以及 `alpha`、`conf_level`。新計畫記錄 `alternative_of`，原 run 的狀態與檔案不變。
- 假設檢查的 alternative 文字、Gate B `assumptions_met` 理由、報告假設檢查段落都附上 `aistat plan --alternative-of <RUN>`（放在 code span 內，不影響 Gate B 數值追溯）。

### 單因子 ANOVA（PR 2）

- 角色 `outcome`（scale）、`group`（nominal / ordinal，3 組以上，每組至少 2 筆）。只有兩組時 Gate A `group_structure` 判 NO，並建議改用 `independent-t-test`。
- **主要結果**：Welch ANOVA（R `oneway.test(var.equal = FALSE)`，SciPy 端依同一公式計算）＋ Games-Howell 事後比較（兩引擎以相同公式計算，p 值用 studentized range 分布：R `ptukey`、SciPy `studentized_range`）。
- **對照**：傳統 F 檢定與 Tukey HSD。R 端直接用 `anova`、`TukeyHSD`；Python 端依同一公式以 studentized range 分布計算，兩者互相驗證。
- 有組別變異數為 0 時 Welch ANOVA 無法計算，報告改以傳統 F 檢定與 Tukey HSD 為主並註明原因。
- **效果量**：η² = SS_between / SS_total；ω² = (SS_between − df_between × MS_within) / (SS_total + MS_within)。
- **假設檢查**：各組 Shapiro-Wilk、Brown-Forsythe Levene（informational，主要結果已是 Welch）。常態不符時建議 Kruskal-Wallis。

### 統計圖表（PR 3）

- 執行成功後，Core 另外產生 `figures.py`，並以 Python 子行程（白名單、逾時）執行，輸出 `figures/figure_N.png` 與 `.svg`；R 引擎的分析也用同一份 figures.py。程式碼與輸出檔雜湊寫入 manifest。
- 圖只畫資料本身（點、箱形、分布、殘差），以及引擎 `results.json` 中已有的數值（例如迴歸殘差、配適值，由引擎輸出）。圖上不寫 p 值或檢定統計量。
- APA 7 版面：無圖內標題、白底、無網格或淡灰網格、座標軸標示變項名稱；報告中以「**Figure N**」與斜體標題說明，並以相對路徑嵌入 PNG。
- 字型：先找系統中的 CJK 字型（Noto Sans CJK、Microsoft JhengHei、PingFang、Heiti 等），找不到而欄位名稱含中文時，圖照樣產生，報告註記缺字型並提示安裝方式。
- 畫圖失敗不影響分析狀態，也不阻擋報告；報告與 execution log 會記錄失敗原因。
- 依賴：`matplotlib` 列為核心依賴。

## 測試決策（Testing Decisions）

- 沿用 v0.1 的 seam（依 `CLAUDE.md` 採推薦答案）：Workspace 門面為主，CLI 少量端對端測試，engine golden case（R / Python 交叉比對），MCP 工具。
- Golden case：
  - Wilcoxon signed-rank exact 用 R `?wilcox.test` 的 Hollander & Wolfe 範例（V = 40, p = .0390625）；常態近似用 `sleep` 資料（V = 45, p = 0.0090907）。
  - Mann-Whitney exact 用 R 文件範例（W = 35, p = 0.2544）；常態近似用 `sleep` 資料（W = 25.5, p = 0.06933）。
  - Fisher 用 Fisher 的 lady tasting tea（p = .4857, OR ≈ 6.408）。
  - ANOVA 用 R 內建 `PlantGrowth`（傳統 F(2, 27) = 4.846, p = .0159）。
- R 內建函式求根精度有限，與 R 內建值的比較採 1e-3 相對誤差；兩引擎之間仍是 1e-6。
- 圖表測試只驗證外部行為：檔案存在且是合法的 PNG / SVG、報告有 Figure 段落、figures.py 可重跑、manifest 有雜湊、畫圖失敗時報告仍會產生。不比對像素。

## 範圍外（Out of Scope）

- Kruskal-Wallis 的執行（只做建議與 `--alternative-of` 的明確錯誤）、Friedman、重複量數 ANOVA、多因子 ANOVA、ANCOVA。
- 大於 2 × 2 的 Fisher's exact test。
- 單尾檢定。
- 互動式圖表、圖表樣式自訂。
- SPSS `.sav` 匯入、`aistat ai`、Web GUI（維持 v0.1 範圍外）。
